# Design Agent Workflow


Use these installed design skill packs deliberately instead of defaulting every UI task to one visual style:

1. **Discover the design problem first**: use `layers-orient` when the request is broad, ambiguous, or cross-functional; continue with Layers skills such as `layers-user-needs`, `layers-product-strategy`, `layers-conceptual-model`, or `layers-interaction-flow` when product decisions are missing.
2. **Generate or compare visual directions before implementation**: use `superdesign` when a page, flow, or component benefits from design drafts, variations, or canvas-based iteration. Verify the CLI is installed and logged in before running Superdesign commands.
3. **Implement with craft guidance**: use `design-taste-frontend` for landing pages, portfolios, marketing pages, and redesigns; use `impeccable` for broader frontend surfaces including dashboards, app shells, forms, settings, onboarding, empty states, design systems, motion, typography, and responsive behavior.
4. **Polish and review**: use `refactor-ui` for a final pass across visual hierarchy, typography, color, spacing, button hierarchy, clutter, empty states, shadows, contrast, and grouping.
5. **Keep accessibility and product constraints active**: combine the design skill with `behavior_validate_accessibility`, existing component conventions, and the smallest relevant browser or build verification.
